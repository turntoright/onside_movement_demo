## Decisions already made (do not relitigate)
1. S3 landing path = rule B → SQS archive-queue (+DLQ) → archiver Lambda → `raw/YYYY/MM/DD/HH/<uuid>.ndjson` (one object per invocation, batch ≤ 100). No Firehose anywhere.
2. DynamoDB tables: `person_state` (pk person_id; attrs version N, visits S = JSON string), `evaluations` (pk checkin_event_id; body S = JSON string), `properties` (pk property_id; property_type S, owner_company_id S). On-demand billing.
3. DynamoDbStore implements the existing StateStore contract exactly (lambdas/standdown_checker/store.py docstring):
   - client API (not resource); ConsistentRead on all reads; property cache per container.
   - commit = TransactWriteItems: Update person_state SET version=:new, visits=:visits with condition `attribute_not_exists(person_id)` when version_read == 0 else `version = :read` (only pass :read when used — LocalStack rejects unused values); plus, for check-ins, Put evaluations with `attribute_not_exists(checkin_event_id)`.
   - TransactionCanceledException: CancellationReasons[1].Code == "ConditionalCheckFailed" → EvaluationExistsError (wins even if [0] also failed); else [0] failed → ConflictError. Without an evaluation, a single-item transaction (or update_item with ConditionalCheckFailedException → ConflictError).
   - First Plan 2 task adds the missing contract test: commit at 0, then 1, then 1 again → ConflictError (stale non-zero version on an existing item); and both-fail leaves state unchanged. Contract suite runs against InMemoryStore and DynamoDbStore (moto).
4. Stand-down Lambda handler (`lambdas/standdown_checker/handler.py`): SQS event → parse EventBridge envelope (`detail-type`, `detail`) from each record body → `process_event` (DynamoDbStore, rules from the bundled CSV, wall-clock now) → PutEvents outbound with Source/DetailType/`Detail=out.detail_json()`/EventBusName env; FailedEntryCount > 0, ValidationError, RetryExhaustedError, or any exception → that record into batchItemFailures; returns {"batchItemFailures": [...]}. Env: PERSON_TABLE, EVALUATION_TABLE, PROPERTY_TABLE, EVENT_BUS_NAME.
5. Archiver Lambda (`lambdas/archiver/handler.py`): write all record bodies (the EventBridge envelopes, one per line) as one NDJSON object to BUCKET under the UTC arrival-hour prefix; any failure → raise (whole batch retried; at-least-once accepted). Batch size 100 (+ maximum batching window if LocalStack honours it — verify; otherwise document).
6. Packaging: `make package` builds `build/standdown_checker/` (package + `standdown_rules.csv` + `tzdata` installed with `pip install --target`, pure python) and `build/archiver/`; Terraform `archive_file` zips them. boto3 comes from the runtime. Rules path resolved next to the package in the zip.
7. Terraform (`infra/terraform/`), hashicorp/aws `~> 6.0`, archive provider; one codebase for local and aws:
   - LocalStack via endpoints (spike's provider block) — choose a mechanism that keeps ONE codebase (e.g. `AWS_ENDPOINT_URL` env from the Makefile + var-driven skip flags/s3_use_path_style, or a dynamic endpoints block) and PROVE it works in the dry run.
   - State per env: `infra/terraform/state/<env>.tfstate` (gitignored).
   - Resources: bucket (name includes account id on aws; force_destroy), 3 tables, bus, rule A (source onside.app, detail-type CheckIn|CheckOut, NO poison filter) → visit-queue (visibility 30 s, DLQ maxReceiveCount 5, DLQ retention 14 d) ; rule B (source onside.app|onside.standdown, detail.poison exists:false) → archive-queue (+DLQ); queue policies; two Lambdas (python3.12, standdown timeout 25 s / 256 MB, archiver timeout 25 s); event source mappings (standdown batch 10 + ReportBatchItemFailures; archiver batch 100); IAM roles/policies; outputs (bucket, table names, bus name, queue URLs).
8. LocalStack compose (`docker-compose.yml`): image 4.14.0, `ulimits nofile 65536`, `LAMBDA_EVENT_SOURCE_MAPPING_POLL_INTERVAL_SEC=0.05`, docker socket mount, PERSISTENCE=0. `make up` = compose down -v + up -d + wait for health + pre-pull `public.ecr.aws/lambda/python:3.12` + reset `state/local/` and `infra/terraform/state/local.tfstate`.
9. Generator for ENV=local|aws (spec §3.2–3.4):
   - `generator.config`: ENVS = ("sim","local","aws"); add scale `local` = Scale("local", 200, 600, 50, 15, 10_000) (and keep `aws`).
   - AWS session per env (local → endpoint http://localhost:4566, region ap-southeast-2, creds test/test; aws → default credential chain, region ap-southeast-2); resource names from `state/<env>/outputs.json` written by `make deploy` (terraform output -json).
   - `setup`: reference data → S3 `ref/*.json` + DynamoDB `properties` (batch write) + local copy; refuses if ref already exists in that env.
   - `generate`: manifest to `state/<env>/manifests/` AND S3 `control/manifests/<run_id>.json` before emitting; PutEvents in send order, batches of 10, retry only the failed entries (bounded), error if still failing; consistency check compares S3 control/manifests with state/<env> runs and says "run make up" (local) / "make reset/destroy" (aws) on mismatch; then settle.
   - `poison --k K`: K malformed events (detail-type CheckIn, detail {"poison": true, "event_id": uuid}), manifest S3 `control/poison/<run_id>.json` + local; waits until DLQ ApproximateNumberOfMessages ≥ expected, timeout 5 min; never settles.
   - `settle` (`generator/settle.py`, spec §3.4): incremental listing of raw/ hour prefixes from run start −1 h; key cache + spool under `state/<env>/`; spool BEFORE cache update; count only this run's ids (uuid5(run_id, seq) for seq < manifest total) per type; gates: every manifest event present, one CheckInEvaluated per distinct check-in, one CheckOutApplied per distinct check-out, one alert per breach evaluation, visit-queue and archive-queue both 0 visible + 0 in flight, then a 30 s quiet period and rescan; compact spool to S3 `compacted/<env>/<run_id>/part-NNNN.ndjson`; write `control/settled/<run_id>.json`; timeout → exit non-zero and keep spool; `make settle ENV= RUN=` resumes.
10. dbt targets `local` and `aws`: DuckDB httpfs + S3 settings (local: endpoint localhost:4566, path style, no SSL, test creds; aws: credential chain), warehouse `warehouse/<env>.duckdb`; Makefile DBT_ENV uses `s3://<bucket>/compacted/<env>/*/*.ndjson` and `s3://<bucket>/ref/` for local/aws (bucket from outputs.json). `make dbt-build ENV=local` must pass with ERROR=0 on LocalStack data (the parity proof on the real AWS-style chain).
11. Makefile (spec §8): `up`, `deploy ENV=local|aws`, `destroy ENV=local|aws` (refuse without explicit ENV on the command line; aws also clears state/aws), `setup/generate/settle/poison ENV=…`, `integration`, `dbt-build ENV=…`, `package`. Keep `ENV = sim` default for data targets; infra targets must not silently default.
12. Tests: unit tests with moto for DynamoDbStore (contract suite), stand-down handler (SQS event fixtures; FailedEntryCount via a stubbed events client), archiver (moto S3), settle (moto S3 + stubbed queue attributes), emitter batching/retry. Integration test (`tests/integration/`, pytest marker, skipped unless `LOCALSTACK=1`): fresh stack, small fixed event set incl. out-of-order, duplicate, orphan check-out and poison; settle; assert person_state, evaluations, compacted objects, DLQ count. One measured LocalStack run at `local` scale (record throughput and wall time in the plan's final task; adjust the `local` scale if > 45 min).
13. Out of scope for Plan 2 (Plan 3): Dagster, CI LocalStack job, real AWS deploy and budget alarm, README rewrite. Do NOT run anything against real AWS. Do NOT push.
